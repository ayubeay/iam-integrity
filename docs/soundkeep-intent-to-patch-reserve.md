## Problem

A persistent gap in music technology: the distance between having a sound in your
imagination and knowing how to construct it. Beginner synthesis courses address this
manually — teach enough concepts that a person can start patching. The originating signal
described seeing a modular synthesizer that "looked like a spaceship control panel" with
no idea where to begin. That is an interface-complexity problem, not a talent problem.

## The durable primitive

Convert musical sound intent, reference audio, descriptive language and available
instrument information into an **explainable synthesis representation** and a guided
patch-building workflow.

    sound intent / reference → sonic feature analysis → synthesis hypothesis
    → abstract patch graph → device-specific implementation → guided execution
    → audio observation → iterative refinement → reproducible sound recipe / provenance

Example: *"a dark metallic pulse that slowly opens up, with an unstable space-radio
texture"* becomes oscillator → modulation → filter → envelope → effects → routing, with an
explanation of why each element is there.

## Abstract patch graph

Represent sounds as reusable **device-independent** patch graphs rather than only finished
audio, translatable into compatible software synthesizers or physical modular environments
where technically possible.

The valuable object is not a saved sample. It is:

    Sound Intent → Abstract Patch → Device Implementation → Audio Result
    → Provenance / Recipe

A musician saves the *knowledge required to reproduce or transform* the sound.

## Evidence discipline

The system must distinguish **what was directly measured** from reference audio, **what
was inferred** about synthesis technique, and **what remains uncertain** — rather than
presenting guessed patches as ground truth.

## Capability amplifier, not replacement

AI sits between the musician and the complexity without eliminating learning:
*"patch output A into input B" · "turn resonance approximately here" · "listen to what
changed" · "that happened because you're modulating cutoff frequency" · "harsher, warmer,
slower, or more unpredictable?"* The person remains the creator while the system
progressively teaches them how the instrument works.

## Future computer-vision extension

Recognize a physical modular rack and construct a machine-readable representation of
modules and available connections, constraining guidance to equipment the musician
actually owns rather than a generic imaginary synthesizer.

## Objective

Not to replace musicianship or synthesis education, but to reduce the intent-to-execution
gap while teaching *why* each routing and modulation decision changes the sound — making
sound-design knowledge computable, transferable and executable.
