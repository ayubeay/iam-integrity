## Core insight

Some execution failures are not caused by insufficient technology, demand, capital,
talent, or an unviable transaction. The actor possesses most of what is required but
cannot cross a specific institutional boundary.

    capable actor → viable product/transaction → jurisdiction/platform requirement
    → identity/entity/banking/payment incompatibility → execution blocked

The missing primitive may not be capital. It may be **institutional admissibility**.

## Absolute boundary

This must **never** become an identity-rental, nominee-person, fake-address,
account-lending, KYC-circumvention, sanctions-circumvention, platform-evasion or
regulatory-arbitrage system.

The architecture does the opposite: **discover the legitimate admissible execution path.**
If no compliant path exists, DENY or DEFER rather than manufacture eligibility.

A technically valid path relying on borrowed identity, hidden beneficial ownership, false
geography, unauthorized accounts or institutional deception is **not** a valid execution
path.

## Core loop

    intent → identify blocked execution → determine exact blocking requirement
    → verify actor / counterparty → identify jurisdictions → identify platform rules
    → determine admissibility requirements → enumerate legitimate routes
    → compare cost / risk / time / control → select admissible route
    → execute through authorized providers → verify resulting permissions
    → execution receipts → monitor requirement/regime changes

## Admissibility questions

What exactly is blocked? Which institution imposes it? What rule creates it? Is it
jurisdictional, regulatory, contractual, technical, financial, tax, identity or merely
operational? **Does the claimed restriction actually exist?** Is there an official
compliant route already available? Who assumes liability? Who owns and controls accounts,
funds, IP, credentials and customer relationships? What happens if the relationship
terminates? Could the structure constitute nominee behaviour, misrepresentation or
prohibited account sharing? Can execution occur without transferring unnecessary
identity, financial or corporate control? What evidence proves successful admissibility?

## Execution Gap Primitives

    viable execution blocked by ONE missing primitive:
    capital · identity · jurisdiction · permission · compliance · settlement
    · connectivity · information · trust · infrastructure · capacity

The system first identifies *which* primitive is missing, then determines whether that
gap can legitimately be resolved.

- Capital gap → `transaction-gap-financing-primitive.md`
- Institutional admissibility gap → this reserve

## New doctrine

**Do not confuse "can technically execute" with "is institutionally admissible to
execute."** Execution infrastructure should model both.
