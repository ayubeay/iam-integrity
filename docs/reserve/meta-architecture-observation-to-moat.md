## Purpose

Name the sequence that connects many independent reserves into one coherent
progression. HELIX governs execution; this sequence governs organizational
evolution — how an organization moves from noticing something in the world
to building a durable advantage. It is larger than HELIX and provides the
stable frame into which future reserves plug.

## Non-goals

Not a new execution lifecycle (that is the HELIX Universal Execution
Lifecycle, which occupies only the Execution span of this sequence) and not
a module. It introduces no technology; it is a map showing how existing
reserves relate. It does not replace or outrank any canonical doc — it
indexes them.

## The sequence

    Observation
      -> Workflow Discovery
      -> Opportunity Evaluation
      -> Admissibility
      -> Execution
      -> Economic Attribution
      -> Receipts
      -> Timeline
      -> Learning
      -> Optimization
      -> Strategic Moat

## Node-to-reserve mapping

- **Observation** — raw signal from the world (founder conversations, market
  data, incidents). Feeds everything downstream.
- **Workflow Discovery** — Operational Workflow Discovery Engine: find
  repeatable broken workflows.
- **Opportunity Evaluation** — Opportunity Intelligence & Evaluation Engine:
  decide whether to pursue (with capital facets via Capital Admissibility,
  Domain-Aware Capital Intelligence, Governed Capital Eligibility).
- **Admissibility** — vLOID + Ownership Proofs vs Execution Rights: may this
  execute, under whose authority?
- **Execution** — the HELIX Universal Execution Lifecycle
  (Discover/Match/Route/Coordinate/Verify/Learn/Optimize), with HELIX
  Exchange, HelixShield, and Execution Assurance as layers/specializations.
- **Economic Attribution** — Flow Economics Engine: what value did this
  execution create or destroy?
- **Receipts** — the receipt substrate: proof of what happened.
- **Timeline** — Universal Execution Timeline: how it happened, replayable.
- **Learning / Optimization** — the lifecycle's Learn/Optimize stages plus
  Backpack's research feedback: history becomes better decisions.
- **Strategic Moat** — AI-Era Moat Doctrine: accumulated, hard-to-copy
  operational history.

## How the reserves compose

Backpack produces hypotheses; Workflow Discovery finds problems; Opportunity
Intelligence evaluates them; HELIX executes them; Flow Economics explains
them; the Universal Execution Timeline remembers them; and the AI-Era Moat
emerges from accumulated history. SURVIVOR is the endurance property that
must hold at every node, not a stage of its own.

## Relationship to existing stack

This document is an index over the canon, not a competitor to it. Each named
reserve remains authoritative for its own node; this doc only asserts the
ordering and the hand-offs between nodes. When a new reserve arrives, place
it by asking which node it improves — consistent with the HELIX evolution-
governance rule (refine existing structure rather than multiply top-level
models).

## Activation condition

Standing synthesis, used at planning and review time to locate any reserve
within the larger progression. Not an implementation task.
