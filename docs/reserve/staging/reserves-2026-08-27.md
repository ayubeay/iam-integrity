## Method note

Two instrument failures were caught during this reconciliation and are worth preserving as
method, since both would have produced confident wrong answers:

1. A concept grep filtered on `--include="*.md"` and could not see `docs/reserve/reserve-index.csv`,
   which would have produced an inconsistent index.

**An empty result is evidence only if the instrument is proven capable of producing a
non-empty one.**

## Reference convention (established 2026-08-27)

A cross-reference in a reserve document is valid if it resolves **either**
repo-root-relative **or** relative to the referencing file's own directory.

Both are in active use: index files (`docs/RESERVED.md`, `docs/reserve/INDEX.md`) and
cross-directory references use repo-root paths; sibling references inside
`docs/reserve/` use bare filenames. A reference resolving under neither is malformed.

Fourteen bare-name references in an earlier draft of this ledger resolved under neither,
because bare sibling names were written from `docs/reserve/staging/`, one directory
deeper than the files they named. Corrected to repo-root form before commit.

**Verification note.** Two successive reference checkers in this session were themselves
the defect. The first matched only lowercase paths and resolved only one way — it
reported six problems while silently skipping every reference containing an uppercase
letter, and its "no MISSING lines" message printed unconditionally even when MISSING
lines existed. The second matched correctly but resolved only file-relative, producing
false positives against the repo's own root-relative convention. Both would have been
believed. *An empty result is evidence only if the instrument is proven capable of
producing a non-empty one — and a gate that always prints "PASS" is not a gate.*
