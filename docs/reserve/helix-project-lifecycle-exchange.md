## Mission

Preserve a future architectural direction for HELIX Marketplace where
software projects are treated as **living execution assets** rather than
static repositories. The objective is not a "graveyard for dead projects"
(the signal was a cemetery-themed dormant-project marketplace — the mechanic
is stronger than the theme), but an execution marketplace where projects
continuously evolve through observable lifecycle states, allowing builders,
contributors, investors, customers, and acquirers to discover opportunities
based on execution history rather than marketing alone.

Philosophy: **projects should not disappear because development pauses.
They should remain discoverable, measurable, and capable of being resumed.**
Not "this project died" but "execution paused" — with receipts explaining
why (funding exhausted, founder refocused, dependency unavailable, waiting
for regulation, seeking cofounder).

## Core doctrine

HELIX does not measure ideas. HELIX measures execution. Every project exists
within an observable execution lifecycle. Possible states: Idea, Planning,
Building, Testing, Beta, Production, Growing, Maintenance, Paused, Dormant,
Seeking Contributors, Seeking Funding, Seeking Customers, Seeking
Acquisition, Revived, Archived. **Lifecycle transitions generate immutable
execution receipts.**

## Project resurrection

Reactivation happens through legitimate execution events, not marketing:
new cofounder joins, new contributor joins, funding milestone reached,
customer pre-purchase, grant received, compute credits donated, API partner
integrated, acquisition offer accepted, original founder returns. Each
transition produces a signed receipt: previous state, trigger, timestamp,
participants, supporting evidence.

## Dormant project exchange

Discovery of dormant execution assets by: technology stack, industry,
development stage, revenue stage, funding status, contributor requirements,
open issues, execution velocity, activity history, trust score, verification
status. Users search for **execution opportunities**, not just startups.
Example project receipt surface: status, reason dormant, last execution,
commits, open issues, revenue, beta users, and "needed to resume" (e.g.
frontend engineer, marketing partner, $8k runway) — making revival
evaluable on evidence.

## Execution receipts

Every project exposes an observable execution timeline. Receipt categories:
Project Created, Repository Connected, Prototype Completed, Beta Released,
Customer Signed, Funding Received, Contributor Joined, Execution Paused,
Dormant, Revived, Archived. Evidence over claims.

## HelixAtlas visualization

Reserve lifecycle-movement visualization: execution heartbeat, lifecycle
timeline, trust evolution, contributor graph, funding history, execution
velocity, dormancy duration, revival events, dependency graph. Living
execution systems, not static repositories.

## Relationship to existing architecture

HELIX Workspace = where builders create. HELIX Marketplace = trust,
relationships, transformation, growth. Project Lifecycle Exchange = makes
execution history observable, turns paused projects into future
opportunities, connects contributors with execution rather than ideas.
Integrates with: HELIX Marketplace, HELIX Workspace, HelixAtlas, vLOID,
VERITY, IAM, OROS, Execution Receipts.

Lifecycle flow: Discover -> Build -> Launch -> Pause -> Recruit -> Fund ->
Resume -> Scale -> Archive.

## Non-goals

Not a cemetery-themed application, not a Product Hunt clone, not a GitHub
replacement, not a crowdfunding platform, not a token speculation platform,
not a project listing website. The focus remains execution governance,
lifecycle observability, and trusted collaboration.

## Activation criteria

Do not begin implementation until: HELIX Workspace is operational; HELIX
Marketplace has an active builder community; execution receipts are mature
and stable; VERITY and IAM are integrated; lifecycle transitions can be
authenticated through execution evidence rather than manual claims. Only
then does the Project Lifecycle Exchange become a first-class Marketplace
capability.
