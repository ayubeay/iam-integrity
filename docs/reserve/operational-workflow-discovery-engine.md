# RESERVE — Operational Workflow Discovery Engine (OWDE)

Status: Future architecture reserve. Opportunity/product-discovery layer.
Activate after VERITY, IAM, OROS, DRIFT, and Commerce Sniper mature. No
execution authority granted here.
Canonical home: iam-integrity/docs/reserve/operational-workflow-discovery-engine.md
Captured: 2026-07-25 (field-service warranty founder — "the workflow is the
product" — but the reserve is the reusable discovery methodology, not the
field-service market. The same pattern recurred across healthcare, lending,
smart homes, music, AI scheduling, and logistics: founders started with
"this workflow is broken," not with AI.)

## Purpose

Search for repeatable operational failures that can be transformed into
governed software execution, rather than searching for industries to
disrupt. Ideas are hypotheses; operational workflows are evidence. Software
should emerge from repeatedly observed execution failures, not assumptions
about markets.

## Non-goals

Not an idea generator and not a market-research report. It does not evaluate
whether a discovered opportunity should be pursued (that is the Opportunity
Intelligence & Evaluation Engine) and does not detect commercial
imbalance/arbitrage (that is Commerce Sniper). Its scope is discovery of
recurring broken workflows, decomposed for comparison.

## Philosophy

Move from Industry -> Idea -> Product -> Customers toward Industry ->
Operational Workflow -> Execution Friction -> Repeatable Pattern -> Governed
Software -> Execution Receipts. Continuously identify fragmented workflows,
repetitive coordination, manual approvals, reconciliation delays, routing
failures, responsibility ambiguity, communication bottlenecks, compliance
friction, and execution uncertainty as candidates for governed software.

## Discovery signals & opportunity formula

Strong opportunities exhibit repetition (the same task thousands of times),
fragmentation (multiple systems/orgs), coordination (several humans exchange
information before execution), accountability gaps (responsibility unclear
afterward), exceptions (failures need expensive manual intervention),
auditability needs (evidence required), and trust dependence. Conceptually:

    Operational Opportunity = Execution Frequency + Coordination Complexity
      + Fragmentation + Accountability Gaps + Compliance Burden
      + Trust Requirements  -  Automation Maturity

The greatest opportunities exist where coordination costs stay high despite
available software.

## Workflow mapping

Every discovered workflow decomposes for cross-industry comparison:

    Intent -> Participants -> Information Flow -> Approvals -> Policies ->
    Execution -> Exceptions -> Settlement -> Receipts

## Relationship to existing stack

Integration: IAM -> VERITY -> DRIFT -> Workflow Discovery -> vLOID -> OROS ->
Commerce Sniper -> Execution -> Receipts. OWDE feeds the Opportunity
Intelligence & Evaluation Engine (discover -> evaluate) and recommends where
modules such as vLOID, OROS, Commerce Sniper, and the Universal Money Router
create durable value. It is the "Workflow Discovery" node of the
Observation-to-Moat meta-architecture.

## Activation condition

Reserve until VERITY/IAM/OROS/DRIFT/Commerce Sniper are mature enough to act
on discovered workflows. Reserve is not build.

## Design principle

Markets describe where value exists; workflows describe how value moves.
Software should optimize the movement of value, not merely digitize existing
processes. Recognize recurring workflow structures across many industries
rather than specializing in one.
